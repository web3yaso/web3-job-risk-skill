## 三、Token风险对照表

### 条款判断标准

| 条款 | 高风险信号 🔴 | 正常范围 🟢 |
|------|------------|-----------|
| Cliff期 | 少于6个月 | 12个月（标准） |
| Vesting总期 | 少于2年 | 4年线性（标准） |
| Token计价方式 | 以token数量计价，无保底 | 以USD计价+价格保护 |
| Token流动性 | 未上所，"计划上所" | 已在主流CEX上市 |
| 团队持仓比例 | >40%（严重中心化） | 15-20%（正常） |
| 员工期权池 | <5%（员工激励不足） | 10-15%（正常） |
| Vesting合同 | 口头承诺，无书面文件 | 独立法律文件 |

### 明显异常信号解读

- **Cliff少于6个月** → 项目方急于套现，对员工极不友好
- **团队持仓>40%** → 上所后随时可能大量抛售，token价值归零风险高
- **只有口头承诺** → 法律保护为零，离职后token极可能拿不到
- **Offer以token数量而非USD计价** → 入职时承诺的"价值"可能入职后缩水90%

## 四、Anon团队替代验证方法

当团队无法doxx时，通过以下方式评估可信度：

1. **链上历史**：过往部署合约是否按时兑现？有无链上恶意行为记录？
2. **社区时间**：核心成员X/Discord发言历史是否连贯一致（几年 vs 几个月）？
3. **审计记录**：是否有知名审计机构报告（Certik、Trail of Bits、OpenZeppelin等）？
4. **机构背书**：是否有doxxed的机构投资人公开背书？
5. **跨平台一致性**：同一人在不同平台的身份叙述是否一致？

## 六、Agency内容合规规则（各司法管辖区）

Agency的SMM/内容岗位面临特殊风险：你制作的内容是否构成"推介token"？

### 各地区规定

**美国（SEC）**：
- 若内容被认定为"solicitation"（向公众推介证券），且未披露受薪关系，可能违反证券法
- 2023年后SEC多次起诉未披露关系的KOL，agency员工同样适用

**香港（SFC）**：
- 2024年新规：社媒推广虚拟资产须明确披露商业关系
- 以个人账号发布但未披露受薪 = 潜在违规

**欧盟（MiCA）**：
- 营销传播须符合信息披露要求
- 发布方（即你）对内容合规负责，不能以"客户让我发的"为由免责

**新加坡（MAS）**：
- 2022年起禁止在公共场所推广数字支付代币服务，包括社媒
- Agency员工替客户在新加坡面向用户发内容需格外谨慎

### 自我保护核查

入职前必须确认的问题（可直接向HR提问）：
- [ ] Agency是否要求所有对外内容披露"paid partnership"或"commercial content"？
- [ ] 合同中是否有条款明确"内容合规责任由客户承担，Agency及员工免责"？
- [ ] Agency是否有内容发布前的合规审核流程？
- [ ] 你是否会被要求以**个人账号**发布客户内容？（个人账号风险远高于公司账号）
- [ ] 如果客户项目后来被认定为scam或证券违规，Agency是否有法律保护条款覆盖员工？

## 七、入职前追问清单（完整版）

**关于公司合规：**
- 公司在哪些司法管辖区持有运营牌照？牌照编号是什么？
- 我的工作合同由哪个法律实体签署？（注意：离岸壳公司签署的合同法律保护弱）
- 公司是否有专职法律合规团队？

**关于薪资安全：**
- 公司目前的现金runway是多少个月？
- 最近一轮融资的close时间和金额？
- 法币薪资是否通过独立的发薪账户发放（而非从运营账户直接转）？
- 如果公司融资失败，员工薪资有何保障机制？

**关于Token条款：**
- Token的vesting条款是否有独立的法律合同文件？（要求看原件）
- Cliff期和vesting总期分别是多少？
- 提前离职时，已vest和未vest的token分别如何处理？
- Token以USD计价还是以数量计价？有无价格下行保护？
- 公司是否会在你锁仓期内大量出售团队持有的token？

**关于岗位职责边界（高风险岗位必问）：**
- 我是否会被要求以个人账号发布内容？
- 内容发布前是否有合规审核流程？
- 如果客户项目出现法律问题，公司如何保护员工？

## 八、求职诈骗防范详细指南

> 本章节对应SKILL.md中的Step 0诈骗前置过滤，提供更详细的背景和防范建议。

### A. 虚招实骗——大厂光环套白狼

**典型手法：**
- 伪造顶级VC（a16z、Paradigm）投资项目，或冒充Binance、OKX等大厂HR
- 安排多轮"正式"面试，只为最后收割
- 索要入职费用：培训费、工牌工本费、背景调查费、签证费

**核心原则：正规Web3公司入职零费用，所有背调费用由公司承担。**

**隐私红线（入职签合同前绝对不提供）：**
- 护照原件扫描件
- 详细银行账户流水
- 家庭住址

### B. 隐形共犯——技术中立不能脱罪

**法律风险：**
明知项目涉嫌洗钱、非法集资，仍提供技术或运营支持，可能构成：
- **帮信罪**（帮助信息网络犯罪活动罪）
- **非法经营罪**

**识别非法项目的信号：**
- 没有实际产品，全靠ICO/IEO募资
- 岗位KPI强制挂钩拉人头/裂变人数
- 涉及大量法币与虚币承兑（OTC）或混币服务
- 只有涨幅汇报，没有技术周报

**入职前验证方法：**
- GitHub查看代码更新频率
- Twitter/Discord观察社区是否有真实技术讨论

### C. 高薪为饵——传销陷阱识别

**话术红旗（听到立即警惕）：**
- "底薪只是零花钱，推广奖金才是大头"
- "入职即送原始币"
- "你不是打工者，你是生态合伙人"
- 岗位名称：社区共建者、增长黑客、生态大使

**判别标准：**
收入80%以上来源于发展下线或诱导用户充值质押 = 资金盘/传销

### D. 致命链接——钓鱼与木马

**高风险文件类型：**
- .exe、.dmg、.scr 后缀：绝对不要打开
- "测试题.zip"、"职位详情.pdf"：高度可疑，即使是PDF也可能隐藏漏洞
- 来自非官方渠道的任何压缩包

**钱包安全铁律：**
- 求职期间，工作设备与存有资产的钱包物理隔离
- 任何要求输入助记词、私钥，或在陌生网页连接钱包的操作：直接拉黑
- 正规求职流程全程无需连接钱包

**如已中招的紧急处理：**
- 已转账：立即联系银行请求拦截，同时向当地警方报案
- 已泄露私钥/助记词：立即将所有链上资产转移到新钱包
- 已下载可疑文件：断网、格式化设备，更换所有相关密码

### 求职安全核查表（面试过程中随时对照）

| 检查项 | 安全信号 🟢 | 危险信号 🔴 |
|--------|-----------|-----------|
| 沟通渠道 | 官方域名邮箱（@company.com） | 仅限Telegram/Gmail/Proton |
| 面试内容 | 专业技术/业务讨论 | 只聊"梦想"和"暴富" |
| 入职费用 | 零费用 | 要求交押金/培训费/设备费 |
| 试岗任务 | 适量Demo演示 | 大规模无偿工作 |
| 钱包操作 | 全程无需连接钱包 | 要求签名/授权/填写助记词 |
| 文件类型 | 无可疑附件 | .exe/.dmg/.scr或可疑zip |

## 九、社会工程学攻击详解：Lazarus/BlueNoroff专项威胁

> 来源：Arctic Wolf安全公司威胁情报报告
> 攻击者：BlueNoroff（隶属Lazarus Group，朝鲜国家级黑客组织）
> 目标：Web3企业员工，尤其是有权访问资金或基础设施的人员
> **求职场景是最高风险入口之一**：陌生人主动联系、要求视频会议、发送文件，完全符合攻击者的标准操作流程。

### 攻击流程（五步）

**第一步：冒充身份建立信任**
- 伪装成：投资人、合作方、法律顾问、猎头、行业KOL
- 接触渠道：邮件、LinkedIn、Twitter/X、Telegram
- 以"商务合作""投资意向""项目咨询"为由发起联系
- 通常使用Calendly发送正式会议邀请，增加可信度

**第二步：引导进入伪造Zoom页面**
- 会议链接指向精心制作的假Zoom页面
- 页面外观与真实Zoom几乎无差别
- 可能模拟"会议正在进行"的界面（部分由AI生成）
- 请求访问摄像头、麦克风

**第三步：ClickFix诱导执行命令**
- 页面提示："你的音频/视频有问题，请按以下步骤修复"
- 要求用户复制一段命令
- 引导在本地终端或PowerShell中粘贴执行
- **关键陷阱：用户是"主动执行"了攻击代码**，看起来像正常操作

**第四步：无文件（Fileless）PowerShell攻击**
- 恶意代码通过PowerShell在内存中运行
- 不在磁盘留下文件，传统杀毒软件难以检测
- 可绕过大多数企业安全系统

**第五步：持久控制与后续攻击**
- 建立持久后门访问权限
- 窃取数据、凭证、私钥
- 对加密资产或公司基础设施发起进一步攻击
- 最终目标：💰资金盗取或敏感信息窃取

### 为什么求职者特别容易成为目标

- 求职期间本就会接受陌生人联系，警惕性降低
- "面试""商务会议"是最自然的视频通话理由
- 求职者急于表现，不易拒绝对方的"技术配合"请求
- Web3从业者通常有链上资产或公司资金访问权限，价值极高

### AI加持让攻击更难识别

- AI生成的会议界面逼真度极高
- AI可实时生成对话内容，使"陌生人"听起来专业可信
- 传统的"感觉不对劲"直觉可能失效

### 防御铁律

**会议安全：**
- [ ] 通过官方渠道独立核实会议邀请方的身份（不要用对方提供的联系方式）
- [ ] 会议前在官方Zoom官网手动输入会议ID，不点击对方发来的链接
- [ ] 真实Zoom/Google Meet页面永远不会要求你在终端执行命令
- [ ] 任何"修复音视频问题"的命令提示 = 立即关闭浏览器

**命令执行：**
- [ ] 浏览器页面中永远不要执行任何命令
- [ ] 终端/PowerShell中永远不要粘贴执行来自网页的代码
- [ ] 即使是"行业知名人士"发来的操作指引，也要独立核实后再执行

**设备隔离：**
- [ ] 求职用设备与存有加密资产的钱包设备物理分离
- [ ] 不在同一台设备上同时进行求职沟通和链上操作

**身份核实：**
- [ ] 投资人/合作方主动联系时，通过其公司官网、已知同事等独立渠道核实身份
- [ ] Calendly邀请不代表对方身份真实，任何人都可以创建

### 已知攻击特征识别

| 特征 | 说明 |
|------|------|
| 主动联系方式 | 邮件/LinkedIn/Twitter冷接触，非熟人介绍 |
| 会议工具 | 伪造Zoom页面（URL非zoom.us官方域名） |
| 异常请求 | 会议中要求在终端执行命令 |
| 攻击组织 | BlueNoroff/Lazarus Group（朝鲜国家级） |
| 主要目标 | Web3从业者、有资金访问权限的员工 |
| 技术特征 | Fileless攻击，不落地文件，难以被杀软检测 |

## 十、从律师实务视角看Web3求职风险

> 来源：邵诗巍律师（上海曼昆律师事务所）系列文章，2023-2026年实务案例汇编
> 作者背景：专注Web3刑事法律，代理案件300+件，含交易所开设赌场案、技术人员帮信案、OTC非法经营案等

### 核心认知：Web3求职者的三大法律盲区

**盲区一：技术岗位没有法律风险**

"我只是写代码，怎么用是甲方的事" —— 这是对技术中立原则的误解。

中国司法实践的判断标准：你提供的技术服务是否对上游犯罪起到"实质性帮助"效果。

真实案例：某数字钱包公司技术维护员工，被异地公安跨省抓捕。原因：其维护的钱包系统具备"多级归集+匿名混币"功能，被认定为帮助信息网络犯罪活动罪。

**盲区二：小平台员工不会被盯上**

与大平台（币安、OKX）相比，小平台员工反而更容易被执法：
- 小平台在境内设有人员，抓捕成本低
- 缺乏KYC、AML等合规防线
- 无执法对接系统，无法体现配合度

**盲区三：项目出海就安全**

法律依据：《刑法》第6条（属地管辖）— 只要人在境内工作，犯罪行为地即认定在国内
《刑法》第7条（属人管辖）— 中国公民在境外犯罪，仍适用中国法律

结论：出海≠安全，境外注册+境内人员工作=刑事风险依然存在

### 四类高危涉赌平台识别（程序员求职必看）

**第一类：Web3游戏平台（链上博彩包装）**

JD关键词：去中心化链游、链上公平博彩、智能合约自动结算、USDT秒结算

识别本质：用虚拟币作筹码，按随机数赔率判断输赢，平台抽水获利 = 开设赌场

真实案例：EOS项目涉赌案（案号：2023苏09刑终372号），技术人员负责合约代码编写，被认定为开设赌场罪从犯

**第二类：永续合约平台（高杠杆赌博包装）**

JD关键词：永续合约撮合开发、高并发交易系统、强平机制、风险控制

识别本质：用USDT押币价涨跌，高倍杠杆，平台收手续费并在清算中持续抽成

真实案例：CCFOX案（案号：2024吉06刑终10号），技术开发人员被认定为开设赌场罪从犯

**第三类：链上预测市场（金融创新包装）**

JD关键词：预测合约、事件合约、AMM资金池、仲裁模型

识别本质：用虚拟币押事件是否发生，按赔率分钱，平台抽成 = 押大小赌博

司法倾向：最高法第146号指导案例精神，此类与传统"押大小"无本质区别

**第四类：赌盘支付平台（支付科技包装）**

JD关键词：聚合支付、跨境结算、USDT支付网关、第四方支付、清结算平台

识别本质：为赌博平台提供充值/提现/兑换底层服务

风险特点：即使你只做技术对接，不知道资金最终流向，仍可能构成帮信罪

看到以下词汇需要立即追问业务模式：

| 关键词 | 可能的真实业务 | 风险罪名 |
|--------|--------------|---------|
| 永续合约/撮合系统 | 高杠杆赌博平台 | 开设赌场罪 |
| 预测市场/事件合约 | 链上赌博 | 开设赌场罪 |
| 链上博彩/公平游戏 | 虚拟币赌场 | 开设赌场罪 |
| 混币/匿名转账 | 洗钱工具 | 帮信罪/洗钱罪 |
| OTC/法币兑换/U商 | 地下钱庄 | 非法经营罪 |
| 节点合伙人/裂变返佣 | 传销机制 | 组织领导传销罪 |
| USDT工资/无合同/TG沟通 | 高风险灰色项目 | 多种 |

### 员工责任差异：被抓不等于同罪

同一家公司出事，不同岗位责任天差地别。判断依据（律师实务总结）：

**第一问：公司与平台是什么关系？**
- 自己做平台控后台 → 核心责任
- 只是给平台引流/推广 → 从属责任

**第二问：你在团队中具体做什么？**
- 老板/技术负责人/财务 → 主犯风险高
- 业务员/投研老师/客服/行政 → 需进一步看工作内容

**第三问：你的钱是怎么拿的？**
- 固定工资 → 相对较低风险
- 按客户交易量提成 → 中等风险
- 按客户亏损分成 → 高度参与，风险极高

**关键辩护空间**：很多普通员工只接触自己那一小块工作，未必了解平台整体运作。司法认定是否构罪，需要证明"明知"且"深度参与"。

### 入职前高危项目自查清单（律师建议版）

**必须核查的四项：**
1. 项目是否在明确、受监管的司法辖区注册（不是BVI/Cayman壳公司）
2. 是否有第三方代码审计报告（Certik、Trail of Bits等）

4. 是否公开项目负责人、团队背景、资金来源路径

- 明确：不直接接触用户资金账户
- 明确：不处理用户个人身份数据
- 明确：不参与拉人推广、分销、代币销售等营销活动
- 保留所有可疑指令的沟通记录（Telegram截图、会议纪要）

### 趋利性执法与异地执法风险

Web3从业者需要了解的执法现实（2025-2026年最新情况）：

**什么是趋利性执法：**
以办案为名谋取经济利益，案件罚没与地方财政捆绑。最高检已通报处理1.9万余件相关案件。

**Web3哪些业务最容易被盯上：**
- 中心化/类中心化交易所（资金量大，容易查封）
- OTC/换汇业务（合规边界模糊，定罪容易）
- 钱包+支付结算服务（被认定为帮信的高频场景）

**识别信号：**
- 多地竞相立案、连续更换指控方向
- 冻结金额明显超过涉案金额
- 以刑事手段介入本属合同纠纷的经济纠纷

**如遭遇异地执法应对原则（家属/当事人）：**
1. 第一时间联系专业刑事律师，不要等
2. 不要轻信"退赃就取保"的承诺
3. 保留所有与工作相关的证明材料
4. 不要在没有律师在场的情况下签署任何文件

## 十一、反向攻击：在职员工也是假Offer的目标

> 来源：The Hacker News, 2022年7月
> 案例：Axie Infinity / Sky Mavis Ronin Bridge被盗案（2022年3月）

### 案例概述

这个案例打破了一个常见误解：**假Offer攻击不只针对求职者，在职的Web3工程师和高管同样是目标。**

攻击者（美国财政部确认为朝鲜Lazarus Group）通过LinkedIn接触Sky Mavis（Axie Infinity母公司）一名高级工程师：
- 以虚假公司名义发起联系
- 安排多轮看似正式的面试建立信任
- 最终发送一份"高薪offer"文件（伪装成PDF）
- 该文件内嵌恶意软件，员工下载后攻击者获得内部网络访问权限
- 最终通过Ronin Bridge盗走约5400万美元（当时约6.2亿美元）

### 关键启示：求职者和在职员工都需要警惕

**对求职者的警示：**
你下载的offer文件本身可能是攻击载体。伪造PDF是Lazarus Group的标准手法，早在2020年"Operation Dream Job"行动中就已广泛使用。

**对在职Web3员工的警示：**
你现有的权限和网络访问是攻击者的真正目标。攻击者并不是真的想雇用你，而是想通过你的设备进入公司基础设施。

### 高危信号（在职员工收到外部offer时）

- [ ] 对方在LinkedIn/Twitter等社交媒体冷接触，非熟人介绍
- [ ] 薪资待遇明显高于市场水平（"极其丰厚的薪酬包"是原文描述）
- [ ] 多轮面试后直接发送文件（而非先进行正式背调）
- [ ] Offer文件需要下载到本机（而非在线查看）
- [ ] 文件格式为PDF、ZIP或任何可执行格式

### 防御铁律（补充第九章）

**文件处理：**
- 任何外部发来的offer文件，在沙箱环境或虚拟机中打开，不在主力工作机上直接运行
- 使用在线PDF查看器（Google Drive、DocSend等）而非本地下载
- 收到offer后，通过官方渠道独立核实该公司是否真实存在

**设备隔离（特别针对有系统权限的工程师）：**
- 求职沟通使用独立设备，与有内部网络权限的工作设备物理分离
- 不在同一台机器上处理外部求职邮件和内部系统访问

**验证offer真实性：**
- 通过公司官网、LinkedIn公司页面等独立渠道核实发出offer的公司是否存在
- 大额薪酬offer + 陌生公司 = 提高警惕级别

### 攻击规模参考

Lazarus Group同类攻击记录（已公开确认）：
- Ronin Bridge：约6.2亿美元（2022年3月）
- Harmony Horizon Bridge：约1亿美元（2022年6月）
- 多起针对防务和航空航天公司的"Operation Dream Job"攻击（2020年至今持续）

## 十二、JPEX案：KOL/推广/技术支持岗位的刑事共犯风险

> 案件：JPEX虚拟资产交易所诈骗案（香港，2023年）
> 涉案金额：超16亿港元
> 受害人数：2700+人
> 相关判例：香港法院，罪名包括串谋诈骗、洗黑钱、欺诈地诱使他人投资虚拟资产

### 案情概述

JPEX平台以"日本交易所"为名进行虚假宣传，实际在香港无牌经营。其推广策略：
- 大量聘用知名KOL（林作、陈怡等）和艺人为平台背书
- 以"高息理财产品"为卖点吸引香港散户
- 香港证监会（SFC）2023年9月公开点名警告后，平台迅速限制提款
- 最终平台跑路，受害者损失超16亿港元

**被捕人员不只是平台内部人员，还包括：**
- 替平台公开推广的KOL和艺人
- 协助推广的中间人

**适用罪名：**
- 串谋诈骗罪
- 洗黑钱罪
- 欺诈地诱使他人投资虚拟资产罪（香港新法，专门针对Web3领域）

### 核心启示：推广岗位 ≠ 法律安全区

JPEX案彻底终结了"我只是推广，不是平台方，不用负责"的认知。

**司法逻辑（香港/中国大陆共通）：**
- 你的推广行为客观上帮助了欺诈活动的实施
- "不知道平台有问题"需要你自己举证，而非检察官证明你知道
- 收取推广费/佣金本身就是"获益于犯罪活动"的证据之一

**与中国大陆案例对照：**

| 角色 | 香港JPEX案 | 中国大陆案例 |
|------|-----------|------------|
| KOL/推广者 | 串谋诈骗罪 | 诈骗罪共犯/帮信罪 |
| 技术开发者 | — | 开设赌场罪从犯（EOS BigGame案、CCFOX案） |
| 支付/清结算 | 洗黑钱罪 | 帮信罪/非法经营罪 |
| 普通业务员 | 视参与深度而定 | 视参与深度而定 |

### 高危岗位JD识别（推广/技术类）

**推广类高危JD特征：**
- 要求推广"高回报""保本收益""稳定年化X%"的虚拟资产产品
- 以社交媒体粉丝数量作为主要录用标准
- 佣金/提成与用户充值金额直接挂钩
- 要求在个人账号发布内容且不披露商业关系
- 平台无SFC/MAS/SEC等监管机构牌照或注册

**技术类高危JD特征（补充第十章）：**
- 开发"资金池管理""抽水逻辑""赔率计算"系统
- 构建OTC换汇、法币兑换通道
- 开发"节点奖励""裂变返佣"智能合约
- 参与"充提币系统""清结算"但无KYC/AML要求

### 匿名团队 + 高薪 = 极高风险组合

JPEX案的另一个教训：平台以"日本交易所"为名，实际创始人信息不透明。

**当以下条件同时出现时，风险等级直接升为🔴：**
1. 核心团队匿名或无法独立核实身份
2. 薪资/佣金明显高于市场（高薪是吸引共犯的标准手法）
3. 平台无任何监管机构牌照或注册
4. 产品宣传包含"高回报""保本""稳定年化"等话术

**这个组合在司法实践中，往往直接支持"明知"的认定** ——即你有理由知道这是问题平台，却仍然参与。

### 香港特别提示

2023年起，香港对虚拟资产服务提供商（VASP）实施强制发牌制度。

求职者核查清单（香港相关岗位）：
- [ ] 平台是否已获香港SFC颁发VASP牌照（可在SFC官网核查）
- [ ] 是否在SFC警示名单上（JPEX被点名警告后仍在招人）
- [ ] 推广内容是否会被认定为向香港公众推介未经授权的投资产品
- [ ] 你的个人推广行为是否受任何合规协议保护

## 十三、伪实习骗局：用"实习机会"白嫖拉新业绩

> 案例类型：交易所"BD实习计划""增长训练营"
> 真实样本：BitTap "BD实习计划内测"

### 套路全流程

这是一种专门针对Web3求职新人的套路，伪装成"实习机会""内测名额""实战训练营"，本质是零成本拉新。

**第一步：包装成学习机会**
- 以"7天带你真实体验交易平台BD工作流程""偏实战的增长训练"等话术招募
- 强调"不是理论课，是实战"，吸引想入行的新人
- 目标人群明确写着"想了解Web3、交易平台、BD、运营、增长方向的新人"

**第二步：要求注册 + KYC作为入场券**
- "完成注册和实名KYC才能进入正式群""才能参加实习"
- 要求用招募方提供的邀请码/邀请链接注册
- 此时你已经为平台贡献了一个KYC实名用户 + 一笔拉新返佣

**第三步：把拉新KPI包装成"实习任务"**
"实习任务"清单实质内容：
- 渠道开发 = 找拉新渠道
- 内容推广 = 免费发推广内容
- 用户转化 = 拉人注册
- 交易量指标 = 让拉来的人产生交易
- 注册数、KYC数、有效用户 = 纯人头指标

**第四步：进阶挑战 = 拉更多人**
- "基础任务完成后参与BD进阶挑战"
- "重点看注册、KYC、有效用户和交易量"
- 本质是让你从"自己刷"升级到"组织别人刷"

**第五步：结算阶段甩锅**
- 通常无底薪，或只有模糊的"表现好可转正"承诺
- 常见操作：组织上百人同时给一个小交易所刷业绩
- 结束后用各种理由（"业绩不达标""内测结束""名额调整"）拒绝转正或不发报酬
- 平台已经拿到了几百个KYC实名用户和交易量数据，目的达成

### 为什么这个套路有效

- 求职新人急于获得Web3行业经验，"实习"听起来是合理的低门槛入口
- "内测""名额有限"制造稀缺感，降低警惕
- KYC、注册这些动作看起来是"正常的产品体验环节"，不像诈骗
- 无底薪被合理化为"实习本来就是学习为主"

### 三层风险

**第一层：劳动剥削**
无底薪试岗，用"实习机会"代替工资，白嫖求职者的推广劳动。即使最后转正，前期大量无偿工作也已经被白拿。

**第二层：传销式结构**
核心KPI是拉人头、注册数、KYC数、交易量，而非真实的BD能力培养。收入（如果有）来自发展下线和拉新，符合传销特征。

**第三层：个人法律风险（最严重）**
你用自己的真实身份完成KYC，并用自己的影响力推广这个交易所。如果这个小交易所本身涉及：
- 开设赌场（永续合约、博彩类）
- 非法经营（无牌交易、换汇）
- 诈骗或资金盘

那么你的推广行为可能构成共犯（参考第十、十二章），你的KYC实名账户也可能成为资金通道而被卷入。你为之刷业绩的"小所"，恰恰是最缺乏合规防线、最容易出事的那一类（参考第十章"小平台员工反而更容易被执法"）。

### 求职者识别清单

正规实习 vs 伪实习对照：

| 维度 | 正规实习 🟢 | 伪实习骗局 🔴 |
|------|-----------|--------------|
| 报酬 | 有实习工资 | 无底薪，或"表现好再说" |
| 入职前提 | 简历、面试 | 必须先注册+KYC某平台 |
| 邀请码 | 不需要 | 要求用招募方邀请码注册 |
| 任务内容 | 真实业务带教 | 拉注册、拉KYC、刷交易量 |
| KPI | 能力成长 | 人头数、注册数、交易量 |
| 规模 | 小批量、有名额管理 | 大批量拉人（上百人）同时进行 |
| 结算 | 按约定发放 | 各种理由拒绝转正/不发钱 |

**核心判断：** 如果一个"实习"要求你先用实名KYC某交易所、用邀请码注册、并以拉新数据作为考核——这不是实习，是拉新骗局。立即退出，不要提交KYC。

### 已经参与了怎么办

- 立即停止拉新推广行为
- 如果已在该交易所完成KYC：评估该平台是否合规，必要时考虑注销账户、提走资产
- 保留招募方的聊天记录、任务要求、邀请链接等证据
- 不要再发展任何下线
- 如该平台后续被定性为非法平台，主动咨询律师评估个人风险

## 十四、传染性面试：代码测试投毒攻击

> 来源：OpenBuild编译，原作者 @officer_secret，2026年5月
> 攻击者：朝鲜国家关联组织（Lazarus Group、APT38）
> 攻击名称：The Contagious Interview（传染性面试）
> 目标：区块链开发者、智能合约审计师、加密工程师、前端、测试岗位

### 为什么叫"传染性"

被入侵的设备或代码仓库会造成进一步感染——供应链风险、团队内部横向扩散。一个开发者中招，可能波及他所在的整个团队和他参与的所有项目。

熊市期Web3岗位缩减、求职竞争加剧，黑客正是瞄准开发者"急于找机会"的心理。

### 攻击流程（完全模仿正规招聘）

**第一步：初次接触**
- 使用AI美化过的LinkedIn虚假账号联系开发者
- 引用真实企业新闻，开出高薪远程岗位
- 重点瞄准Web3、区块链、前端、测试岗位

**第二步：建立信任**
- 发送专业PDF文件、Figma原型、项目需求文档
- 安排Google Meet等视频面试
- "HR面试官"完成常规提问后，突然布置居家技术测试题并结束通话

**第三步：投递恶意软件**
诱导方式包括：
- 克隆GitHub/Bitbucket代码仓库
- 下载OneDrive文件
- 安装所谓"线上会议工具"（如GrassCall）

常见的恶意代码触发方式：
- 恶意 `package.json` 脚本，如 `"postinstall": "npm run dev"`，执行 `npm install` 时自动运行
- 依赖包中混入与项目无关的冗余库（简单React项目里混入 ethers、wagmi 等加密库）
- 工具文件中隐藏伪装的 WebAssembly（WASM）模块
- 虚假软件安装信息窃取程序

**第四步：窃取资产**
程序一旦运行，窃取：MetaMask插件、钱包文件、助记词、浏览器凭证、`~/.ssh` 与 `.env` 文件中的私钥、Cookie和登录令牌、本地任意文件；植入后门；篡改剪贴板钱包地址。

### 真实案例：MetaLamp如何识破

头部Web3开发公司MetaLamp收到了一个"去中心化电商平台"的代码审核邀请。识破过程值得每个开发者学习：

**疑点1**：项目托管在Bitbucket上，完全没有提交记录
**疑点2**：招聘的是技术总监岗位，但仓库里只有两个粗糙的Truffle智能合约，代码粗暴堆砌在React框架中——岗位级别与代码质量严重不符
**疑点3**：`package.json` 里有可疑依赖包 `rollup-plugin-polyfill-route`——17天前才上传到npm，周下载量仅90次，第一次上传就直接是1.0.2版本，极不寻常
**核心恶意逻辑**：代码中有 `eval(JSON.parse(b))`，会解析从恶意服务器获取的数据并直接执行；恶意包被伪装成Vite打包器的垫片插件，混入 `vite.config.js`

### 其他真实攻击案例

**仿冒Fireblocks攻击（2026）**：诈骗者伪装成Fireblocks招聘人员，推出虚假"Fireblocks扑克平台"项目，诱导审核GitHub仓库。使用EtherHiding技术，利用区块链智能合约作为命令控制节点。

**ChainSeeker.io盗钱包攻击**："Crazy Evil"黑客团伙搭建虚假Web3公司，在LinkedIn、WellFound、CryptoJobsList发布岗位，引导求职者联系Telegram上的"首席营销官"并下载GrassCall软件窃取钱包凭证。

**前端居家测试题陷阱**：React/Vite基础项目中被植入服务端恶意库、Base64编码的WASM后门，甚至用体积庞大无用的3D模型文件（如.glb文件）掩盖恶意载荷。部分 `postinstall` 钩子伪装成正常Webpack代码。

### 开发者识别清单：拿到代码测试时逐项核查

**仓库层面：**
- [ ] 仓库有没有正常的提交历史？（无提交记录 = 高危）
- [ ] 代码质量是否与招聘岗位级别匹配？（招技术总监却只有粗糙代码 = 可疑）
- [ ] 为什么用Bitbucket等不常见托管，而非候选人可见历史的方式？

**package.json层面：**
- [ ] 有没有 `postinstall`、`preinstall` 等自动执行钩子？
- [ ] 依赖里有没有与项目类型无关的库？（纯前端项目混入加密钱包库 = 可疑）
- [ ] 依赖包是否冷门？去npm查上传时间、周下载量、版本历史——新近上传、下载量极低、版本号异常 = 高危

**代码层面：**
- [ ] 有没有 `eval()`、`Function()` 动态执行从外部获取的数据？
- [ ] 有没有读取 `.env`、`~/.ssh`、钱包路径的代码？
- [ ] 有没有可疑的WASM模块、Base64编码的大块数据、异常的二进制文件？

> 💡 提示：可以把 `package.json` 和可疑代码直接交给AI（如Claude）做安全审查——仅通过查看 `package.json`，AI就能识别出高危恶意依赖。

### 防御方案

**全面核验：**
- 通过企业官方招聘页面核实招聘人员身份，仅用企业官方邮箱沟通
- 正规面试极少要求克隆陌生仓库、安装第三方工具

**沙箱隔离（最重要）：**
- 所有代码测试在虚拟机或容器中运行
- 隔离个人钱包、浏览器插件、账号凭证
- 使用VS Code工作区信任模式
- **个人加密资产环境与工作设备物理隔离**

**安装前审查：**
- 仔细检查 `package.json` 异常脚本、冗余依赖、未知 `postinstall` 钩子
- 优先使用 HackerRank、CoderPad、GitHub Codespaces 等正规测试平台
- 拒绝直接下载文件

**危险信号速查：**
- 面试突然结束后立刻布置代码任务
- 私人邮箱联系
- 高薪过度承诺
- 要求安装"面试软件"
- 临时推迟会面、却让你"先看代码做准备"（MetaLamp案中的典型套路）

**通用最佳实践：**
- 全平台开启二次验证，监控钱包动态
- 关注Fireblocks、微软、趋势科技等安全机构资讯，跟进攻击变种
